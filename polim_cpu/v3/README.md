## 与第二版的区别

- 保留全域 `H≥0`。每个原始单元都使用完整 `dx`，体积与来源的矩形流线定义一致；不再把首尾单元当作半格。原始地形、宽度、坐标和网格间距在全部断点保持逐位一致。
- 对相连且 `H≥1 m` 的至少三格冰体使用 Q1 BP；小于 1 m 的薄冰和不足三格的冰块使用局地 SIA 近似。阈值只决定动量方法，不改变冰厚、质量或物理域。当前 93–94 格动量矩阵远小于全域 4094 格矩阵；这不是删除无冰区。
- 通量采用供冰单元限流。冰可以流入原先无冰的网格；积累增加冰量，消融只移除现有冰量，过量潜在消融单独记录。没有人为厚度下限。图中分别显示 `H>0` 与 `H≥1 m`，数值扩散的薄冰尾部不视为观测冰川长度。
- 水平焓随质量通量输运，使用深度平均速度；表面积累进入焓时采用列内混合近似。厚冰执行焓柱方程；薄冰采用表面温度极限，其热交换单独记账。孤立的厚冰列也执行柱热力，不会因动量使用 SIA 而跳过热过程。
- 年度空间质量平衡采用现有 MonthlyTI 公式和源参数，按每年开始时的表面高度缓存，完整保存这个缓存供续算。密度统一为 900 kg/m³，时间统一为 365 天/年。

## 使用

从项目根目录运行，输出目录必须是新目录。普通合成演示不需要 LIA 真实分支授权：

```powershell
python -m polim_cpu.v3 demo --out polim_cpu/runs/my-v3-demo --device cuda
python -m polim_cpu.v3 report polim_cpu/runs/lia-2387-v3-pilot-v1
```

中途保存后在相同代码和运行环境下续算：

```powershell
python -m polim_cpu.v3 demo --out polim_cpu/runs/my-v3-resume --device cuda --stop-step 11
python -m polim_cpu.v3 resume --out polim_cpu/runs/my-v3-resume
```

需要主动重复工程检查时，使用新目录：

```powershell
python -m polim_cpu.v3 verify --out polim_cpu/runs/my-v3-check --gpu
```

真实 LIA 配置的启动入口会核对项目控制器、研究分支授权、冻结配置和代码指纹。本次分支已正常结束并关闭运行授权；不能用“续算”自动扩展到更长时期或其他系统。原有主线运行字段和接受数保持不变，接受数量仍为 58/191。
