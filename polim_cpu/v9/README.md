# 可运行的多支流 BP 演化原型

双击项目 `polim_cpu/Open_Model.cmd`。首次授权计算生成结果；已有完成结果时直接打开播放器，不重复计算。命令入口为 `python -m polim_cpu.v9`。播放器明确回放实际保存结果，不在浏览器中假装计算。

本版本在同一原生网格内接通：全域 BP 速度 → 守恒冰厚与焓输运 → 温度扩散及底融 → 局地温度相关流变 → 下一次全域 BP。真实输入是已配对的 2387 重建几何，保留 178230 个节点、353096 个三角形和全部源支流连接；不进行水平粗化、几何平滑或冰厚垫高。

为先交付完整流程，BP 沿用能跑原生网格的 3 个垂向节点，温度使用 9 个节点。两支流的汇流位于内部共享网格，传递速度应力、冰量及焓；没有人为支流间侧壁。节点控制面积按三角形面积三等分，积分冰量与初始线性有限元冰量一致。每条内部面通量使用同一数值并以相反符号记入两侧，复用 v4 的保守输运。

本次冻结计算为一小时，整体速度每十分钟更新一次，期间输运按 CFL0.35 子步推进。气候使用已有包中的1441年数据，表面条件在这一小时内固定于初始高程。沿用项目基准参数和已授权的气候冰温初始化、0.05 W/m² 地热假设。流动因子采用已有压力校正 Arrhenius 与含水率关系，在−10°C处匹配原项目基准 A。

第一版采用明确的开放计算域假设：BP 外周零有效载荷，冰可流出且计入收支，域外没有冰输入，也不向域外扩展冰缘。这还不是经过核实的冰缘、岩壁与末端物理边界。已知异常高速保留原值，不截断、不通过参数拟合掩盖。本次为短时研究原型，不声称真实历史、观测拟合或科学验收。

温度模块复用既有隐式焓柱求解器，加入 BP 应变热，保留水分排出和底融。水平焓只随保守冰量通量输运一次；未解析垂向平流，表面增冰在相应 sigma 层内混合。H<1m采用既有薄柱表面温度闭合并记录能量交换。这些简化在冻结计划中公开。

每个完整时间端点保存 H、E、底融、气候条件、速度与时间，并用哈希封存；每轮 Newton 也保存状态。轻量状态文件被占用时，计算继续并写入替代状态快照。已完成的指纹不重复计算，后续扩展按项目执行约束另立版本。

主要借鉴与复用：已通过标准算例的 v8 BP 弱形式与边界认识；已跑通原生网格的 v7r1 BP 数值核心；v4 守恒输运；v3 温度、质量平衡与流变关系。原 PoLIM 与各依赖的 NOTICE/LICENSE 继续适用。原 PoLIM 引用：Wang et al. (2020), doi:10.1016/j.cageo.2020.104526。

运行与结果位于 `polim_cpu/runs/v9-integrated-native-evolution-v1`，可视界面位于 `polim_cpu/reports/integrated-model-v1`。根目录当前状态和版本计划决定数值授权；`prepare` 用于登记、`run` 用于唯一计算、`render` 用于结果展示，不能绕过已有指纹或重跑已完成阶段。
